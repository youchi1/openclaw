# 2026-04-13 — NO_REPLY Garbage Text Suppression (HC-005)

## Summary

Fixed NO_REPLY garbage text from context pollution leaking to users as visible
Telegram messages. Models (especially GPT 5.4 via Codex) sometimes output
`NO_REPLY` glued to garbage text after processing multi-select button callbacks.

## The Problem

HeadClaw customers see garbled messages in Telegram like:

```
NO_REPLY출장샵assistant to=functions.message մեկնաբDelays 大发分分彩json
{"action":"send","channel":"telegram","target":"...","message":"What kind of content?","buttons":[...]}
```

The model intended silence (NO_REPLY) but context pollution caused it to
prepend garbage characters (CJK spam, symbols, combining marks) before the
token or between the token and a leaked JSON tool call.

Upstream issues: openclaw/openclaw#25592, openclaw/openclaw#64976

## Root Cause

Two bugs in the NO_REPLY suppression logic:

### Bug 1: Regex too narrow

`startsWithSilentToken` used `[\p{L}\p{N}]` (letters/numbers only) to detect
text glued after NO_REPLY. This missed:

- Symbols: `NO_REPLY♀♀♀♀ to=function` (`♀` is `\p{So}`)
- Combining marks: `NO_REPLYైంది to=` (Telugu vowel sign is `\p{M}`)
- Space-separated garbage: `NO_REPLY 𜿿 to=fun`
- Punctuation-separated: `NO_REPLY: explanation`, `NO_REPLY—note`

### Bug 2: Strip instead of suppress

When the regex did match (e.g. `NO_REPLYhello`), the code stripped the
NO_REPLY prefix and delivered the remaining text (`hello`) to users. For
garbage text like `NO_REPLY출장샵assistant...`, this delivered `출장샵assistant...`
as a visible message.

## Fix

1. **Broadened regex** from `[\p{L}\p{N}]` to `\S` — any non-whitespace after
   NO_REPLY means the model intended silence and the rest is garbage.

2. **Drop instead of strip** — `normalizeReplyPayload` and `agent-runner-execution`
   now suppress the entire payload (return null / skip) instead of stripping
   the prefix.
