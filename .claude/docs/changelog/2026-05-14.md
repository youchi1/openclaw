# 2026-05-14 — Fix publish-flow footgun (HC-008 unrelated to cron; pure tooling)

## Summary

`@youchi1/openclaw@2026.5.7-patched.1` was published from `patched/2026.4.12`
source (with the version label overridden), shipping a tarball that was missing
upstream's `dist/subagent-registry.runtime.js` fix and none of the HC-001..008
patches we re-applied on `patched/2026.5.7`. The version label said 5.7, the
contents were 4.12. Surfaced as a `subagent cleanup finalize failed` warning
storm on a customer VPS.

## Root cause

Two structural holes in the patching flow:

1. **Publish tooling lived only on `patched/2026.4.12`.** `scripts/publish-headclaw.sh`
   and `scripts/postinstall-rename.mjs` were committed back in April on the
   2026.4.12 branch and were never carried forward. The 2026.5.7 branch had
   no publish script of its own, so the obvious place to run the publish from
   was the OpenClaw repo on 2026.4.12 — which is the wrong tree.
2. **Two-checkout state.** The 2026.5.7 upgrade was done in a `git worktree`
   (`openclaw-probe/`) while the main `OpenClaw/` checkout stayed on 2026.4.12.
   With the publish script discoverable only on 2026.4.12, the failure mode
   became silent.
3. **No build-time invariant.** The publish script took a version arg and ran
   `pnpm build` on whatever working tree it was sitting in. Nothing asserted
   that the branch matched the version.

## Fix

- Moved `publish-headclaw.sh` and `postinstall-rename.mjs` from `scripts/` to
  `.claude/scripts/` so they ride along with every future bookkeeping restore
  (`git checkout patched/OLD -- .claude/`).
- Adjusted path references:
  - `postinstall-rename.mjs` now resolves `package.json` via `"../.."` (was `".."`)
  - Publish script wires postinstall to `node .claude/scripts/postinstall-rename.mjs`
    and adds `.claude/scripts/postinstall-rename.mjs` to the `files` array
- Added a branch invariant at the top of `publish-headclaw.sh`: aborts unless
  `git rev-parse --abbrev-ref HEAD` equals `patched/<VERSION_BASE>`.
- Updated `.claude/rules/patching.md`:
  - Upgrade workflow explicitly forbids worktrees / second clones
  - Publish section documents the branch invariant
  - All `scripts/...` paths replaced with `.claude/scripts/...`

## Verification

- `@youchi1/openclaw@2026.5.7-patched.1` tarball inspected: matched 2026.4.12
  dist shape (28,614 files, no `CronNested` symbol, hashed
  `subagent-registry-Dq8wIf0_.js` instead of the unhashed entry).
- Upstream `openclaw@2026.4.12` tarball confirmed to have the same missing
  `subagent-registry.runtime.js` → bug is upstream's, but upstream already fixed
  it in 2026.5.7 by declaring an explicit `tsdown.config.ts` entry. Our fix is
  purely about ensuring the right source tree gets built.
