## Verification workflow (new)

For each patch considered for dropping, we ran in order:

1. **Read linked issues** in PATCHES.md and check whether their closing PRs match our fix.
2. **Diff our changed files against `v2026.5.7`** — find the equivalent functions upstream.
3. **Cherry-pick our patch onto pristine v2026.5.7** — empty commit signals subsumption,
   conflict signals partial coverage.
4. **Run our existing patch tests against pristine v2026.5.7** — failing tests show
   what upstream missed; import errors signal API drift only.
5. **Write a new verification test** that exercises the original bug scenario directly,
   then run it against pristine upstream. Passing test = genuinely subsumed.

Four such verification tests were written and committed as a separate small commit
(`test(HC): upstream-subsumption verification tests`) before bookkeeping. They live alongside
their respective source files so they keep running in CI and catch any future upstream
regression that re-introduces these bugs.

This workflow is now documented in `.claude/rules/patching.md` for future upgrades.
